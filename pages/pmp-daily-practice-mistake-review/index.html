错题的价值不在于记住14个答案，而在于发现自己反复踩中的决策陷阱：

# 3. 一套通用的六步判断法

遇到“项目经理应该做什么”“下一步”“首先”类题目时，按以下顺序判断：

  1. 判状态：事情已经发生，还是仅可能发生？
  2. 找责任人：产品价值、团队障碍、治理权责分别由谁负责？
  3. 看权限：项目经理能否直接处理，是否真的需要升级？
  4. 排顺序：是否应先了解、记录、评估，再行动？
  5. 选最小有效动作：优先直接、具体、协作式地解决问题。
  6. 警惕绝对词：强制、立即升级、一定失败、全部开会通常需要额外证据。

# 二、问题、风险与应对边界

这一组错题暴露出最明显的薄弱点：没有先根据时间状态区分问题与风险。

状态 管理对象 首要动作 典型工件
已经发生并影响项目 问题 记录、分析、解决 问题日志
尚未发生但存在不确定性 风险 识别、分析、规划应对、监控 风险登记册
风险应对后仍存在 残余风险 重新评估并更新风险信息 风险登记册
一个团队的交付可能影响另一个团队 依赖风险 记录、分析并持续监控 风险登记册/风险报告

# 错题1：在线存储库已经不可用

题目： 软件团队因互联网不稳定，已经无法使用在线存储库。项目经理应该怎么办？

  • A. 将问题记录在问题日志
  • B. 在每日站会上讨论
  • C. 上报发起人
  • D. 查看风险日志并执行应对计划

🔴 我的答案：D　　🟢 正确答案：A

# 📝 原始答案解析

精讲《过程组：实践指南》117 节；选A，关键句：团队无法使用在线存储库。此为问题而非风险，D排除。按问题处理流程三大步骤（确认问题-分析问题-解决问题）来处理，将问题记入问题日志是第一步，A正确。B站会只提出问题，不讨论，错误。C项目经理应自己先积极主动的解决问题，而非直接上报，偏消极，排除。

# 判断链

  1. 关键词是“已经无法使用”，事件已经发生；
  2. 已发生的事件是问题，不是风险；
  3. 问题管理从确认和记录开始，因此先进入问题日志；
  4. 站会适合暴露障碍，不适合展开长时间的问题解决；
  5. 项目经理尚未主动处理，不能直接升级发起人。

💡 一句话规则：已发生进问题日志，未发生进风险登记册。

📖 参考：《过程组：实践指南》第117节。

# 错题2：风险应对后出现残余风险

题目： 已识别风险发生并采取应对措施后，又出现残余风险。项目经理应该怎么做？

  • A. 启动应急计划
  • B. 通知发起人并申请资金
  • C. 重新审视风险登记册中的所有风险
  • D. 审查成本管理计划

🔴 我的答案：A　　🟢 正确答案：C

# 📝 原始答案解析

选C，精讲《过程组：实践指南》161 节；A. 应急计划通常是针对特定的已识别风险及其应对措施制定的，而题干中已经采取了应对措施后仍出现残余风险，说明原有的应急计划可能并不完全适用，不能直接启动应急计划来处理残余风险，需要重新评估和考虑，所以该选项不正确。B. 在没有对残余风险进行全面评估和分析之前，就通知发起人申请资金是不合适的。首先要确定残余风险的性质、影响程度等，再决定是否需要申请资金以及申请多少资金，故该选项也不合适。C. 出现残余风险意味着风险情况发生了变化，需要项目经理重新审视风险登记册中的所有风险。一方面可以检查对已识别风险的评估和应对措施是否合理，是否需要调整；另一方面也可以查看其他风险是否受到影响，是否需要更新应对策略，该选项正确。D.审查成本管理计划与处理残余风险之间没有直接的关联。虽然风险可能会对成本产生影响，但在这种情况下，首先要关注的是风险本身的处理，而不是直接审查成本管理计划，所以该选项不符合要求。

# 判断链

残余风险说明原有风险状态和应对效果发生了变化。此时不能机械套用原应急计划，而应重新评估：原风险是否需要更新、应对措施是否有效、其他风险是否受到影响，以及是否需要新的应对策略。尚未评估影响就申请资金同样顺序错误。

💡 一句话规则：应对后仍有风险，先重评风险全貌，再选新的应对。

📖 参考：《过程组：实践指南》第161节。

# 错题3：敏捷软件团队不承诺最终日期

题目： 混合项目的重大设计变更已经批准，进度和预算影响已知。敏捷软件团队负责人拒绝承诺最终交付日期，而硬件团队依赖该软件。项目经理应该怎么做？

  • A. 将依赖延迟风险加入风险登记册并持续监控
  • B. 向更高管理层升级
  • C. 强制软件团队遵守交付日期
  • D. 要求软件团队改用预测型方法

🔴 我的答案：B　　🟢 正确答案：A

# 📝 原始答案解析

选A，精讲《过程组：实践指南》105 节；选A，这种情况可能会对项目进度和交付产生重大影响，因此需要在风险管理计划中进行记录和监控，以便及时采取措施应对。选项B不是最佳选项首先应尝试通过风险管理和团队协作来解决问题，而不是立即升级。选项C错误，强制要求交付日期不符合敏捷方法。选项D错误，冒然采用预测性方法可能不适合软件开发过程和客户的需求。

# 判断链

软件交付日期的不确定性尚未造成实际延期，但可能阻塞硬件团队，因此属于依赖风险。项目经理应先登记、分析、制定应对并监控。直接升级跳过了正常风险管理；强制承诺或强行切换生命周期既不尊重敏捷方式，也没有解决不确定性的根因。

💡 一句话规则：未来依赖可能延迟，先做风险管理，不要先升级。

📖 参考：《过程组：实践指南》第105节。

# 本组错因总结

我的错误不是不会背“问题日志”和“风险登记册”，而是做题时过早被“互联网不稳定”“团队拒绝承诺”“残余风险”等显眼词吸引，没有先判断事件所处的时间状态。

以后先问一句：

它现在已经造成影响了吗？

# 三、团队障碍、冲突与沟通策略

PMP情境题通常偏好主动、直接、尊重和协作式处理。升级、强制和扩大会议范围不是默认首选。

# 错题4：成员不敢向PO说明故事无法完成

题目： 团队成员无法在当前冲刺结束前完成用户故事，而且十分胆怯，不愿向产品负责人说明。项目经理应该怎么做？

  • A. 鼓励其在下一次每日站会上汇报
  • B. 在下一次站会上询问其他成员能否接手
  • C. 与该成员制定沟通计划并分享经验
  • D. 为该成员安排工作会，解决当前挑战

🔴 我的答案：A　　🟢 正确答案：D

# 📝 原始答案解析

精讲《敏捷实践指南》18 节；选D，D项目经理通过会议与该团队成员沟通，积极帮助其克服困难，D正确。AB中都涉及“下一次”解决，偏消极。一旦发现问题，项目经理应第一时间解决，不能推到“下一次”。C敏捷团队一般无需制定沟通管理计划，且该团队成员面临是需要克服的挑战，为非经验，排除。

# 判断链

障碍已经暴露，服务型领导应立即帮助成员解决，而不是等下一次会议。工作会能保护胆怯成员的心理安全，也能聚焦分析具体障碍。A、B都延迟处理；C把一个待解决的挑战误当作经验管理问题。

💡 一句话规则：障碍已经出现，就立即协助移除，不要等待例会。

📖 参考：《敏捷实践指南》第18节。

# 错题5：正式会议中干系人持续冲突

题目： 技术性很强的项目处于初级阶段，关键干系人需求不明确、技术不理解、参与度不高，正式会议中出现大量冲突。项目经理应该怎么做？

  • A. 开展非正式会议，确认干系人的顾虑
  • B. 邀请关键干系人的技术代表参会
  • C. 上报发起人决策
  • D. 请技术总监指导

🔴 我的答案：B　　🟢 正确答案：A

# 📝 原始答案解析

选A，精讲《过程组：实践指南》40 节；A. 在项目初级阶段，关键干系人对需求和技术存在诸多问题，正式会议又引发了意见不和与冲突，此时开展非正式会议是较好的方式。非正式会议氛围相对轻松，能让干系人更自由地表达顾虑和想法，有助于项目经理深入了解问题根源，以便针对性地解决，缓解冲突，提高干系人参与度，该选项正确。B. 虽然技术代表能提供技术方面的支持和解释，但无法直接解决干系人对需求不明确以及参与度不高的问题，且可能会使会议更加复杂，增加协调成本，不能从根本上解决当前面临的主要问题，所以该选项不太合适。C. 项目处于初级阶段，项目经理应首先尝试自己解决问题，积累经验和树立解决问题的能力。直接上报给发起人可能会让发起人认为项目经理缺乏解决问题的能力，而且发起人可能不了解具体细节，难以做出准确决策，故该选项不是首要选择。D. 技术总监能在技术方面提供帮助，但对于干系人需求不明确和参与度不高的问题，技术总监的作用有限，不能全面解决当前会议中出现的各种问题，所以该选项也不是最有效的解决办法。

# 判断链

题干同时出现需求不清、参与度低和冲突，根因不只是技术知识不足。非正式会议更有利于干系人表达真实顾虑、澄清期望并建立信任。技术代表只能解释技术，无法替代干系人参与；直接上报或只找技术总监也没有处理关系问题。

💡 一句话规则：正式场合谈不拢，先用非正式沟通找真实顾虑。

📖 参考：《过程组：实践指南》第40节。

# 错题6：关键成员辞职后团队士气低落

题目： 关键成员认为新任项目经理能力有限并辞职，其他成员困惑且士气低落。项目经理接下来怎么做？

  • A. 上报发起人
  • B. 了解团队困惑原因，明确剩余成员角色和任务
  • C. 挽留离职成员
  • D. 审核风险并记录到风险登记册

🔴 我的答案：D　　🟢 正确答案：B

# 📝 原始答案解析

选B，精讲《过程组：实践指南》84 节；选项A：上报项目发起人。虽然与项目发起人沟通是重要的，但此情景不需要上报发起人；选项B：了解团队成员困惑原因，明确剩余成员角色和任务。这个选项直接针对了问题的核心。了解团队成员的困惑是解决问题的第一步，同时明确剩余成员的角色和任务可以为团队提供清晰的方向，有助于稳定团队情绪和恢复士气。可以选。选项C：考虑到该成员已经辞职，且题干中描述的是其他团队成员的困惑和士气低落，因此当前的重点应是稳定现有团队，而不是过度关注已辞职的成员。选项D：团队士气低落的问题已经发生， 不是一个风险。 不选。

# 判断链

辞职和士气下降都已经发生，不是未来风险。当前重点是稳定仍在项目中的团队：理解困惑、重新建立清晰方向、澄清角色与任务。只关注离职人员或立即升级，都无法解决现有团队的问题。

💡 一句话规则：成员离开后，先稳住现有团队，再处理后续资源安排。

📖 参考：《过程组：实践指南》第84节。

# 错题7：职能经理安排项目外任务

题目： 职能经理要求团队支持与项目无关的任务，已经影响项目生产力。项目经理下一步应该做什么？

  • A. 要求产品负责人与职能经理沟通
  • B. 将其记录为风险并持续监控
  • C. 直接与该职能经理沟通，避免进一步延迟
  • D. 召集所有职能经理开会

🔴 我的答案：D　　🟢 正确答案：C

# 📝 原始答案解析

精讲《敏捷实践指南》18 节；选C，项目经理的职责之一是确保团队的资源和生产力不受干扰。在这种情况下，职能经理的要求干扰了项目工作，影响了团队的生产力，项目经理应该主动采取措施解决这种资源冲突。选项D不是最佳选项，与所有职能经理沟通没有必要，通过直接联系有冲突的职能经理来解决问题会更有效率，这不仅可以避免不必要的会议浪费时间，也能够更快地寻求理解与合作，从而更好地解决资源冲突。选项A错误，与职能经理沟通不是产品负责人的职责。选项B错误，这是已经发生的问题，不是还未发生的风险。

# 判断链

冲突对象非常明确，项目经理应直接与对应职能经理沟通。召集所有职能经理扩大了问题范围，效率更低；产品负责人不负责跨部门资源协调；生产力影响已经发生，不能只记为风险。

💡 一句话规则：单点冲突找单点责任人，不要默认扩大会议范围。

📖 参考：《敏捷实践指南》第18节。

# 错题8：制定基本规则时只有两人发言

题目： 制定团队基本规则时只有两名成员参与讨论，规则因此偏向这两人的意见。项目经理应该如何避免？

  • A. 带着预先建议的基本规则参会
  • B. 会前要求所有成员提交新想法
  • C. 延长会议时间
  • D. 会前明确所有成员在会议中作出贡献的期望

🔴 我的答案：B　　🟢 正确答案：D

# 📝 原始答案解析

选D，精讲《过程组：实践指南》85 节；选D，在会议开始之前，项目经理应该明确告诉团队成员他们在讨论中的角色和预期贡献。例如，项目经理可以说明每个人都应该准备好分享自己的观点、提出建议或参与讨论。这可以帮助确保所有团队成员都有参与感从而避免会议中只有少数人发言，确保每个人都有机会表达自己的意见。通过提前设定期望，团队成员会更有动力在会议中积极参与。A.可能削弱团队所有权，导致后续规则执行阻力。B.虽能会前收集了意见，但无法保证会议中公平讨论。还是解决不了题干的问题。C.治标不治本，无法解决参与动力或结构性问题。

# 判断链

收集想法不等于保证成员在讨论中真正参与。项目经理应在会前设定参与规范，让每个人知道自己需要准备并贡献观点。预设规则会削弱团队所有权；单纯延长时间不能解决参与动力和结构问题。

💡 一句话规则：提升参与度，先明确参与期望，而不是只增加时间或收集材料。

📖 参考：《过程组：实践指南》第85节。

# 错题14：干系人病休导致关键反馈中断

题目： 一个项目处于建设关键时刻，相关项目干系人因休病假，无法参与沟通会议且不提供项目关键反馈，项目经理本应该如何避免该问题的发生？

  • A. 上报发起人
  • B. 制定干系人参与计划
  • C. 记录问题日志
  • D. 与干系人沟通，商讨沟通和反馈方案

🔴 我的答案：B　　🟢 正确答案：D

# 📝 原始答案解析

选D，精讲《过程组：实践指南》92 节；A.上报发起人和C记录问题日志属于事后解决，不属于避免问题发生。B制定干系人参与计划是要对干系人进行管理，让干系人多参与和支持，而题干生病导致的信息传递问题，不属于干系人管理范畴。选择D，因其通过事前协商沟通与反馈机制的设计，直接避免因干系人缺席导致的信息阻塞。

# 判断链

题目问“如何避免”，因此要选事前预防动作。D直接建立沟通与反馈机制，可进一步落地为替代联系人、授权方式、异步渠道和反馈时限；A、C都是事件发生后的处理。B虽涉及干系人参与，但相比D不够直接，不能仅凭“计划”二字忽略题干中的信息连续性问题。

📚 PMI校准： 2026年PMP考试内容大纲“人员域”要求分析并裁剪沟通以满足干系人需要、执行干系人参与计划并管理干系人期望；本题考查的是这些要求在具体场景中的落地动作。

💡 一句话规则：关键反馈不能依赖单次参会，事前约定替代沟通与反馈机制。

📖 参考：《过程组：实践指南》第92节；PMI 2026 PMP考试内容大纲“人员域”。

# 本组错因总结

这一组反复出现“范围过大”或“动作过晚”的错误：

  • 本该立即工作会，却等下一次站会；
  • 本该找一个职能经理，却召集所有职能经理；
  • 本该找真实顾虑，却只补充技术代表；
  • 本该稳定现有团队，却把问题记成风险。

可迁移原则是：

选择最直接、最小范围、最尊重当事人且能解决根因的动作。

# 错题9：新发起人接手项目

题目： 原发起人离职，新发起人即将接手。项目经理首先应该怎么做？

  • A. 与新发起人确认项目背景
  • B. 将新发起人识别为不确定性风险
  • C. 向团队介绍新发起人
  • D. 让新发起人重新签署项目计划

🔴 我的答案：B　　🟢 正确答案：A

# 📝 原始答案解析

选A，精讲《过程组：实践指南》37 节；选项A：这是一个非常关键的步骤。新发起人可能对项目的前情、目标、当前进展等并不十分了解。与其确定项目背景，不仅可以让新发起人对项目有一个全面的了解，也有助于项目经理了解新发起人对项目的期望和态度，从而更好地进行后续的合作。选项B：这个选项合适。虽然新发起人的加入确实带来了一定程度的不确定性，但将其直接视为风险可能并不利于建立良好的合作关系。更重要的是，应该通过积极的沟通和合作来减少这种不确定性。选项C：这确实是一个必要的步骤，但在此情境下，它并不是项目经理首要应该做的事情。在介绍新发起人给团队之前，项目经理自己需要先了解并熟悉新发起人。选项D：在新发起人刚刚接手，还未充分了解项目的情况下，就要求其重新签署项目计划并不合适。更何况，项目计划的调整应该基于项目的实际进展和新发起人的意见来进行，而不是简单地重新签署旧计划。

# 判断链

发起人交接首先需要建立共同认知：项目背景、目标、当前状态、关键约束和双方期望。只有完成对齐，才适合介绍团队、讨论计划或评估具体不确定性。直接把人视作风险既不利于合作，也跳过了最基本的沟通。

💡 一句话规则：关键干系人变化时，先对齐背景与期望。

📖 参考：《过程组：实践指南》第37节。

# 错题10：迭代评审中商业功能不足

题目： 迭代评审后，干系人反馈看到的技术功能比商业功能更多。项目经理应该怎么做？

  • A. 在下一次迭代回顾中讨论
  • B. 在下一次迭代规划前与产品负责人一起回顾
  • C. 在下一个每日会议中与团队讨论
  • D. 等到下一次迭代规划时让产品负责人回顾

🔴 我的答案：A　　🟢 正确答案：B

# 📝 原始答案解析

选B，精讲《敏捷实践指南》28 节；A. 迭代回顾是团队内部总结改进的环节，但干系人反馈的商业功能不足问题需优先与产品负责人对齐需求，而非仅在团队内部讨论，响应时效性不足；B. 干系人反馈指向产品待办事项优先级偏差（技术功能多于商业价值功能），产品负责人负责定义需求优先级。迭代规划前与产品负责人同步问题，可及时调整待办列表，确保后续迭代聚焦商业价值，符合敏捷 “快速响应变化” 原则；C. 每日会议聚焦当日任务进展，属于短周期同步，不适合处理需求优先级调整这类需与产品负责人协同的策略性问题；D. 未明确与产品负责人的提前沟通机制。导致规划会议中需求调整准备不充分，影响效率。

# 判断链

商业功能不足说明产品待办事项的价值排序出现偏差，而产品负责人负责价值和优先级。应在规划前完成对齐，让产品负责人有时间调整待办列表。迭代回顾处理团队过程改进，每日会议处理短周期协作，都不是解决产品优先级问题的最佳场合。

💡 一句话规则：产品价值排序偏差，规划前先找产品负责人。

📖 参考：《敏捷实践指南》第28节。

# 错题11：业务主管要求最终上线决策权

题目： 业务主管要求获得系统最终“是否上线”的决策权。项目经理应该怎么做？

  • A. 用专业证据说服主管信任项目团队
  • B. 与项目发起人会面，确定是否接受该权责请求
  • C. 直接在RAM中确认主管负责决策
  • D. 要求客户承诺由主管负责

🔴 我的答案：A　　🟢 正确答案：B

# 📝 原始答案解析

选B，精讲《过程组：实践指南》18 节；A. 仅通过专业证据说服可能忽视主管的业务视角（如系统运营实际需求），易引发对立，且决策权调整属治理范畴，非单纯技术沟通可解决；B. 项目发起人负责整体治理，主管要求最终决策权涉及权责变更，需发起人评估对项目目标的影响（如验收标准、干系人协作），协调业务单元与客户干系人达成共识，符合 “重大变更上报管理层” 流程；C. RAM 应在规划阶段确定，开工会议临时调整需经变更流程，未经评估直接分配责任可能导致权责混乱，引发客户干系人不满；D. “承诺” 非项目管理标准流程，权责调整需通过正式变更或治理机制。客户无权单方面决定其他干系人的权责，此做法缺乏流程依据，可能引发多方争议。

# 判断链

这不是技术可信度问题，而是治理结构和最终决策权变化。项目发起人应评估其对验收、协作和项目目标的影响，并协调相关方形成正式安排。RAM不能未经评估就直接修改，客户承诺也不能替代正式治理机制。

💡 一句话规则：重大决策权变化是治理问题，不是靠专业说服解决。

📖 参考：《过程组：实践指南》第18节。

# 本组错因总结

角色题不能只看“谁最懂技术”或“谁职位最高”，而要看这个角色是否拥有对应职责：

  • 产品价值找产品负责人；
  • 重大权责找发起人或治理层；
  • 团队障碍由项目经理主动协助；
  • 交付方案和估算尊重团队自组织。

# 错题12：建筑项目收尾前的关键动作

题目： 建筑项目即将收尾，在正式收尾前的关键动作是什么？

  • A. 提交项目最终报告
  • B. 确认各类款项已经结清
  • C. 通知PMO项目收尾
  • D. 确保项目取得相关部门的资格证书

🔴 我的答案：A　　🟢 正确答案：D

# 📝 原始答案解析

选D，精讲《过程组：实践指南》167 节；选项A：错误，项目最终报告，是在项目收尾阶段做的事情，不是“收尾前”做的事情。选项B：错误，也是收尾阶段做的事情，不是收尾前。 而且因为项目具体情况、账期、争议等其他因素，不是必须的关键动作。选项C：错误，也是收尾阶段做的事情，不是收尾前。通知PMO项目收尾是必要的，但这通常是在确认所有收尾工作（包括取得必要的资格证书）都已完成之后的事情。选项D：确保项目取得相关部门的资格证书。这是建筑项目收尾前的关键动作，因为没有相关部门的资格证书，项目无法被正式验收和使用。这些证书是确保项目符合所有法律和技术要求的必要文件。国内的比如，建筑工程质量认证、消防安全认证、环保认证、规划许可证及审批文件、特殊行业许可证等等。 不要被“资格证书”误导，以为是PMP这样的个人资格的。

# 判断链

题眼是“收尾前”。建筑项目应先确认题干所指的相关合规证明或批准，才具备正式验收和使用条件。最终报告、款项结清和通知PMO属于收尾阶段工作，不能替代合规前置条件。具体文件名称和要求应以适用法律、合同及主管部门规定为准。

💡 一句话规则：先满足法定验收条件，再进行行政和合同收尾。

📖 参考：《过程组：实践指南》第167节。

# 错题13：CPI为0.933时如何评价绩效

题目： BAC=100万美元、EV=70万美元、AC=75万美元、CPI=0.933，应如何评价项目？

  • A. 将按计划完成
  • B. 比计划更容易完成
  • C. 难以按计划完成
  • D. 无法按计划完成

🔴 我的答案：D　　🟢 正确答案：C

# 📝 原始答案解析

选C，精讲《过程组：实践指南》154 节；选C，CPI<1表示项目的成本超支，如果这种趋势继续下去，项目将难以按计划完成。选项D不完全准确，尽管项目确实表现不佳，但目前的数据不能直接得出项目一定无法完成的结论，而是难以按原计划完成。A和B明显错误。

# 判断链

CPI = EV / AC = 70 / 75 ≈ 0.933。CPI小于1，说明每花费1美元只获得约0.933美元的价值，成本效率不佳并存在超支趋势。因此项目更难按原计划完成，但仅凭当前数据不能断言一定无法完成，D的语气过于绝对。

指标 公式 大于1 小于1
CPI EV / AC 成本效率较好 成本超支/效率较差
SPI EV / PV 进度提前 进度落后

💡 一句话规则：指数小于1代表绩效不佳，不代表项目必然失败。

📖 参考：《过程组：实践指南》第154节。

# 六、从14道错题提炼出的六类陷阱

# 1. 把“下一步”做成“下一次”

题目已经说明障碍存在时，等到下一次站会、回顾会或规划会通常响应过慢。先判断能否立即开展一次聚焦的问题解决活动。

# 2. 把已发生的问题登记成风险

这是本轮最重复的错误。看到“不稳定”“辞职”“影响生产力”等词时，不要马上联想到风险登记册，必须先判断影响是否已经发生。

# 3. 把局部冲突扩大化

只有一个职能经理造成资源冲突时，直接与其沟通；不要默认召集所有职能经理。最小有效动作通常比大范围会议更合适。

# 4. 把协作问题变成升级问题

项目经理应先在权限内了解、沟通、分析和处理。只有超出权限、正常协商失败或涉及重大治理时才升级。

# 5. 忽略角色与事件边界

产品价值问题应由产品负责人处理，且最好在迭代规划前准备；重大决策权变化应由发起人协调，不能通过修改RAM或技术说服草率解决。

# 6. 被绝对化选项吸引

“强制”“一定无法”“立即升级”“全部人员开会”往往过度承诺。除非题干给出明确触发条件，否则优先选择评估、沟通和渐进处理。

# 七、一页速记表

题干信号 优先判断
关键干系人可能缺席、关键反馈可能中断 📡 事前约定替代联系人、反馈渠道和时限

风险应对后仍有影响 🔄 重新评估残余风险和整体风险登记册
团队障碍已经暴露 🏃 立即协助解决，不等下一次会议
干系人在正式会议中冲突 ☕ 非正式沟通，识别真实顾虑
明确的单点资源冲突 🤝 直接找对应职能经理沟通

# 八、下次做题的自检清单

在选择答案前，用20秒完成以下检查：

  • [ ] 事件已经发生了吗？
  • [ ] 这是问题、风险、变更，还是治理事项？
  • [ ] 题目问“首先”“下一步”还是最终解决方案？
  • [ ] 正确责任人是项目经理、产品负责人、团队还是发起人？
  • [ ] 我是否跳过了了解、记录或影响评估？
  • [ ] 是否可以先直接沟通，而不是升级？
  • [ ] 是否可以缩小处理范围，而不是召集所有人？
  • [ ] 选项是否包含强制、必然、全部等过度措辞？

# 结语

这14道错题共同指向一个核心：PMP情境题关注的不是“动作最大”，而是“判断准确、顺序正确、角色匹配、协作有效”。

真正值得记住的不是A、B、C、D，而是这条决策链：

先判断事实状态 → 找到责任角色 → 了解和评估 → 选择最小有效动作 → 必要时再升级。

掌握这条链路后，题目换人、换行业、换项目方法，依然可以稳定推导出答案。
