PMP49个过程与ITTO

# PMP 49个项目管理过程：内容、输入、工具与技术、输出详解

适用口径：预测型项目管理。 本文以 PMBOK® Guide 第六版及 PMI《Process Groups: A Practice Guide》的49过程模型为主线。新版PMBOK强调原则、绩效域与价值交付，但49过程仍是理解预测型项目管理闭环和PMP情景题的重要结构。

# 一、先理解ITTO，不要直接死背

每个过程都可以用同一个逻辑理解：

输入 Input：开始这个过程前已经掌握什么
    ↓
工具与技术 Tools &amp; Techniques：项目团队如何处理输入
    ↓
输出 Output：过程完成后产生什么，并流向后续过程

# 1. 四类高频输入

  1. 项目管理计划：说明“项目准备怎么管”，包括子管理计划和范围、进度、成本基准。
  2. 项目文件：记录项目的动态信息，例如风险登记册、问题日志、假设日志、需求文件、经验教训登记册。
  3. 事业环境因素（EEF）：项目团队通常不能直接控制的内外部环境，例如组织文化、法规、市场、基础设施、人员能力。
  4. 组织过程资产（OPA）：组织可复用且可更新的过程、模板、历史数据、知识库和经验教训。

# 2. 三层工作绩效流

  • 工作绩效数据：执行中采集的原始事实，例如完成工时、缺陷数、实际成本。
  • 工作绩效信息：经过某个控制过程分析后的结论，例如进度落后5天、CPI为0.9。
  • 工作绩效报告：面向决策者整合展示的信息，例如项目周报、仪表盘、状态报告。

# 3. 三类成果状态

  • 可交付成果：执行过程产生的产品、服务或结果。
  • 核实的可交付成果：经过控制质量，证明技术上符合要求。
  • 验收的可交付成果：经过确认范围，由客户或发起人正式接受。

# 4. 变更的标准闭环

发现问题或机会
→ 分析原因与影响
→ 提出变更请求
→ 实施整体变更控制
→ 批准/拒绝/推迟
→ 指导与管理项目工作实施批准变更
→ 控制质量与确认范围验证结果

# 三、整合管理

负责把各知识领域连接成一个整体。项目经理对整合负有不可转移的核心责任。

# 4.1 制定项目章程｜启动过程组

# 过程作用

正式授权项目或阶段，明确高层级目标、边界、成功标准，并赋予项目经理调动资源的权力。

# 主要输入

  • 商业文件：商业论证、效益管理计划
  • 协议：合同、备忘录、服务协议等
  • 事业环境因素（EEF）
  • 组织过程资产（OPA）

# 工具与技术

  • 专家判断
  • 数据收集：头脑风暴、焦点小组、访谈
  • 人际关系与团队技能：冲突管理、引导、会议管理
  • 会议

# 主要输出

  • 项目章程
  • 假设日志

# 销售看板项目示例

公司决定建设销售看板，由发起人批准目标、预算上限和项目经理权限。

# PMP高频辨析

项目章程由发起人批准；项目经理通常参与编制，但不是自己给自己授权。

# 4.2 制定项目管理计划｜规划过程组

# 过程作用

把各子管理计划和三大基准整合为一套经批准、可执行、可监控的总体管理方案。

# 主要输入

  • 项目章程
  • 其他规划过程的输出
  • 事业环境因素
  • 组织过程资产

# 工具与技术

  • 专家判断
  • 数据收集：头脑风暴、核对单、焦点小组、访谈
  • 冲突管理、引导、会议管理
  • 会议

# 主要输出

  • 项目管理计划：各子管理计划、范围/进度/成本基准及其他管理组件

# 销售看板项目示例

汇总销售看板的范围、排期、成本、质量、沟通、风险和干系人管理安排。

# PMP高频辨析

项目管理计划是一套整合文件，不是只有进度表；基准一旦批准，不能随意修改。

# 4.3 指导与管理项目工作｜执行过程组

# 过程作用

领导和实施项目管理计划中的工作，产出可交付成果并处理执行中的问题。

# 主要输入

  • 项目管理计划
  • 项目文件：变更日志、经验教训登记册、里程碑清单、进度计划、风险登记册等
  • 批准的变更请求
  • 事业环境因素、组织过程资产

# 工具与技术

  • 专家判断
  • 项目管理信息系统（PMIS）
  • 会议

# 主要输出

  • 可交付成果
  • 工作绩效数据
  • 问题日志
  • 变更请求

控制范围不是拒绝变化，而是确保变化经过评估和批准。

# 五、进度管理

# 主要输入

  • 资源/风险管理计划、成本基准
  • 经验教训、进度计划、团队派工、资源日历、风险登记册/报告、干系人登记册
  • 事业环境因素、组织过程资产

# 工具与技术

  • 专家判断
  • 访谈
  • 引导
  • 威胁策略：上报、规避、转移、减轻、接受
  • 机会策略：上报、开拓、分享、提高、接受
  • 应急应对策略
  • 备选方案和成本效益分析
  • 多标准决策

# 主要输出

  • 变更请求
  • 项目管理计划更新
  • 项目文件更新

# 销售看板项目示例

针对源系统延期，采用提前接入模拟数据、设置缓冲并制定应急切换方案。

# PMP高频辨析

应对措施必须与风险优先级相称，并明确风险责任人与行动责任人。

# 11.6 实施风险应对｜执行过程组

# 过程作用

执行已批准的风险应对措施，确保风险行动真正落地。

# 主要输入

  • 风险管理计划
  • 经验教训登记册、风险登记册、风险报告
  • 组织过程资产

# 工具与技术

  • 专家判断
  • 影响力
  • PMIS

# 主要输出

  • 变更请求
  • 项目文件更新

# 销售看板项目示例

按计划启用模拟数据开发、安排备用人员并提前执行性能压测。

# PMP高频辨析

规划了应对不等于风险已管理，必须在执行中真正落实。

# 11.7 监督风险｜监控过程组

# 过程作用

跟踪已识别风险、监督剩余风险和次生风险、识别新风险，并评价风险过程有效性。

# 主要输入

  • 风险管理计划
  • 问题日志、经验教训、风险登记册、风险报告
  • 工作绩效数据
  • 工作绩效报告

# 工具与技术

  • 技术绩效分析
  • 储备分析
  • 风险审计
  • 会议

# 主要输出

  • 工作绩效信息
  • 变更请求
  • 项目管理计划更新
  • 项目文件更新
  • 组织过程资产更新

# 销售看板项目示例

每周检查源系统延期风险触发条件、应对效果和应急储备消耗，并识别新风险。

# PMP高频辨析

风险发生后转为问题处理；风险审计检查应对和风险管理过程是否有效。

# 十一、采购管理

管理从组织外部获得产品、服务或成果的全过程及合同关系。

# 12.1 规划采购管理｜规划过程组

# 过程作用

确定哪些内容需要外购、如何采购、采用何种合同与供应商选择方式。

# 主要输入

  • 项目章程
  • 商业论证、效益管理计划
  • 范围/质量/资源等管理计划和范围基准
  • 里程碑、需求文件/跟踪矩阵、资源需求、风险和干系人登记册
  • 事业环境因素、组织过程资产

# 工具与技术

  • 专家判断
  • 市场调研
  • 自制或外购分析
  • 供方选择分析
  • 会议

# 主要输出

  • 采购管理计划
  • 采购策略
  • 招标文件
  • 采购工作说明书（SOW）
  • 供方选择标准
  • 自制或外购决策
  • 独立成本估算
  • 变更请求
  • 项目文件/组织过程资产更新

# 销售看板项目示例

决定购买BI工具还是自主开发，确定合同类型、招标要求和评分标准。

# PMP高频辨析

采购工作说明书要清晰到供应商能够报价，但不能不必要地限制其解决方案。

# 12.2 实施采购｜执行过程组

# 过程作用

获取卖方响应、评估建议书、选择卖方并授予合同。

# 主要输入

  • 采购相关管理计划和成本基准
  • 经验教训、进度计划、需求文件、风险和干系人登记册
  • 采购文档
  • 卖方建议书
  • 事业环境因素、组织过程资产

# 工具与技术

  • 专家判断
  • 广告
  • 投标人会议
  • 建议书评价
  • 谈判

# 主要输出

  • 选定的卖方
  • 协议/合同
  • 变更请求
  • 项目管理计划更新
  • 项目文件更新
  • 组织过程资产更新

# 销售看板项目示例

组织BI厂商答疑会，按功能、价格、服务和风险评分并完成合同谈判。

# PMP高频辨析

投标人会议要确保所有潜在卖方获得相同信息，维护公平。

# 12.3 控制采购｜监控过程组

# 过程作用

管理采购关系、监督合同绩效、处理变更和索赔，并正式关闭合同。

# 主要输入

  • 采购/风险/需求/变更管理计划及进度基准
  • 假设日志、里程碑、质量报告、需求文件/跟踪矩阵、风险和干系人登记册
  • 协议、采购文档、批准的变更请求
  • 工作绩效数据
  • 事业环境因素、组织过程资产

# 工具与技术

  • 专家判断
  • 索赔管理
  • 绩效审查、挣值和趋势分析
  • 检查
  • 审计

# 主要输出

  • 结束的采购
  • 工作绩效信息
  • 采购文档更新
  • 变更请求
  • 项目管理计划更新
  • 项目文件更新
  • 组织过程资产更新

# 销售看板项目示例

检查BI供应商交付、服务级别和付款里程碑，处理合同变更并完成合同验收。

# PMP高频辨析

合同争议按合同约定的索赔和争议解决机制处理，项目经理不能单方面改合同。

# 十二、干系人管理

识别并分析相关方，通过适当参与策略获得支持、降低阻力。

# 13.1 识别干系人｜启动过程组

# 过程作用

识别能够影响项目或受项目影响的人员、群体和组织，分析其利益、影响和潜在作用。

# 主要输入

  • 项目章程
  • 商业论证、效益管理计划
  • 沟通/干系人参与管理计划
  • 变更日志、问题日志、需求文件
  • 协议
  • 事业环境因素、组织过程资产

# 工具与技术

  • 专家判断
  • 问卷调查、头脑风暴
  • 干系人分析、文件分析
  • 干系人映射/表现：权力利益方格等
  • 会议

# 主要输出

  • 干系人登记册
  • 变更请求
  • 项目管理计划更新
  • 项目文件更新

# 销售看板项目示例

识别销售负责人、财务、数据团队、管理层、信息安全、运维和供应商。

# PMP高频辨析

应尽早识别并持续更新；遗漏高权力干系人会带来重大项目风险。

# 13.2 规划干系人参与｜规划过程组

# 过程作用

根据干系人的需要、期望、利益和影响力，制定促进其有效参与的策略。

# 主要输入

  • 项目章程
  • 资源/沟通/风险管理计划
  • 假设日志、变更日志、问题日志、进度计划、风险登记册、干系人登记册
  • 协议
  • 事业环境因素、组织过程资产

# 工具与技术

  • 专家判断
  • 标杆对照
  • 假设与制约、根本原因、干系人分析
  • 优先级排序
  • 思维导图、干系人参与度评估矩阵
  • 会议

# 主要输出

  • 干系人参与计划

# 销售看板项目示例

对高权力高利益的销售负责人重点管理，对普通使用者采用定期沟通和试用反馈。

# PMP高频辨析

比较当前参与程度与期望参与程度，再设计策略，不是要求所有人都“领导”项目。

# 13.3 管理干系人参与｜执行过程组

# 过程作用

与干系人沟通协作、管理期望、处理关切和问题，促进其支持项目决策和执行。

# 主要输入

  • 沟通/风险/干系人参与及变更管理相关计划
  • 变更日志、问题日志、经验教训、干系人登记册
  • 事业环境因素、组织过程资产

# 工具与技术

  • 专家判断
  • 反馈
  • 冲突管理、文化意识、谈判、观察与交谈、政治意识
  • 基本规则
  • 会议

# 主要输出

  • 变更请求
  • 项目管理计划更新
  • 项目文件更新

# 销售看板项目示例

组织指标评审，协调销售与财务口径争议，推动负责人按时确认和验收。

# PMP高频辨析

管理干系人参与强调主动互动和解决问题，而不是单向发送信息。

# 13.4 监督干系人参与｜监控过程组

# 过程作用

监控干系人关系和参与状态，并调整策略，以维持或提高参与有效性。

# 主要输入

  • 资源/沟通/干系人参与管理计划
  • 问题日志、经验教训、项目沟通、风险登记册、干系人登记册
  • 工作绩效数据
  • 事业环境因素、组织过程资产

# 工具与技术

  • 备选方案、根本原因、干系人分析
  • 多标准决策、投票
  • 干系人参与度评估矩阵
  • 反馈、演示
  • 积极倾听、文化意识、领导力、人际网络、政治意识
  • 会议

# 主要输出

  • 工作绩效信息
  • 变更请求
  • 项目管理计划更新
  • 项目文件更新

# 销售看板项目示例

发现销售负责人由支持转为抵制，分析原因并调整汇报频率、参与方式和决策机制。

# PMP高频辨析

干系人的权力、利益和态度会变化，所以登记册和参与计划必须持续更新。

# 十三、按过程组快速串联49过程

# 1. 启动：2个

  • 制定项目章程
  • 识别干系人

逻辑：先获得授权，再找到会影响项目的人。

# 2. 规划：24个

所有十大知识领域都要规划。记忆主线：

  • 整合：制定总体计划；
  • 范围：收需求、定范围、建WBS；
  • 进度：定活动、排顺序、估工期、出计划；
  • 成本：估成本、定预算；
  • 质量、资源、沟通、风险、采购、干系人：分别设计管理规则和方案。

# 3. 执行：10个

  • 整合：指导工作、管理知识；
  • 质量：管理质量；
  • 资源：获取资源、建设团队、管理团队；
  • 沟通：管理沟通；
  • 风险：实施风险应对；
  • 采购：实施采购；
  • 干系人：管理干系人参与。

# 4. 监控：12个

  • 整合：监控项目工作、整体变更控制；
  • 范围：确认范围、控制范围；
  • 进度、成本、质量、资源、沟通、风险、采购、干系人各有一个控制或监督过程。

# 5. 收尾：1个

  • 结束项目或阶段。

# 十四、最需要区分的ITTO关系

容易混淆 正确关系
可交付成果 → 核实 → 验收 指导与管理项目工作产生可交付成果；控制质量产生核实成果；确认范围产生验收成果
数据 → 信息 → 报告 执行采集绩效数据；各控制过程形成绩效信息；监控项目工作整合成绩效报告
变更请求 → 批准变更 各过程可提出变更请求；整体变更控制作出批准、拒绝或推迟决定；指导与管理项目工作实施批准变更
问题与风险 风险尚未发生，记录在风险登记册；问题已经发生，记录在问题日志
管理质量与控制质量 管理质量关注过程、审计和预防；控制质量关注成果、检查和缺陷发现
控制质量与确认范围 控制质量由项目团队判断成果是否正确；确认范围由客户/发起人正式接受
建设团队与管理团队 建设团队提升能力和凝聚力；管理团队处理绩效、反馈和冲突
管理沟通与管理干系人参与 管理沟通确保信息有效流动；管理干系人参与通过互动影响态度和支持程度

# 十五、学习建议：不要按几百项孤立背诵

建议按以下顺序掌握：

  1. 先记住49过程的位置和每个过程的目的；
  2. 再记住关键输出，因为输出经常成为后续过程输入；
  3. 重点掌握三条链：绩效链、成果验收链、变更控制链；
  4. 工具与技术按类别理解，例如数据收集、数据分析、决策、人际技能，而不是逐字死背；
  5. 做题时先定位“管什么知识领域”，再定位“正在规划、执行还是监控”。

真正的考试能力不是背出全部ITTO，而是根据情景判断：现在缺少什么输入、应该使用什么管理动作、下一步应产生什么输出。
