# PMP人员域：团队领导、沟通、干系人协作与冲突处理

新版PMP人员域强调的不只是“管理团队”，而是**建立共同愿景、形成信任、让团队自主负责、对齐干系人期望、促进知识传递并持续解决冲突和障碍**。

![团队领导与障碍处理](/donot-eat-fish/img/project-management/pmp-exam/team-leadership-impediment-removal.png)

## 第八记：管理沟通

### 1. 沟通模型

有效沟通不仅是发送信息，还包括编码、媒介、解码、确认理解和反馈。题目出现“第一次听说”“报告缺失信息”“团队理解不一致”时，通常应先检查沟通计划、需求分析和反馈闭环。

### 2. 沟通方法

| 方法 | 适用场景 | 示例 |
|---|---|---|
| 互动式 | 需要实时对齐、共同决策、处理争议 | 会议、电话、视频、研讨会 |
| 推式 | 信息明确，需主动发送给特定受众 | 邮件、报告、通知、备忘录 |
| 拉式 | 信息量大、受众广、异步获取 | 内部网站、知识库、项目门户 |

沟通渠道数量：`N(N-1)/2`。人数增加会迅速提高沟通复杂度，因此应通过结构化会议、角色接口、信息发射源和共享平台降低成本。

### 3. 沟通管理计划

至少说明：受众、信息、格式、频率、责任人、技术、语言、升级路径、保密和反馈要求。沟通不满意时，不能只“多发邮件”，而应审查需求是否变化、计划是否适配、信息是否被理解。

## 第十一记：让干系人参与

![干系人与沟通决策图](/donot-eat-fish/img/project-management/pmp-exam/stakeholder-communication-decision.png)

### 1. 沟通题与干系人题的区别

- 信息传递失败、格式/频率/渠道不合适：沟通管理；
- 不支持、不参与、抵制、满意度下降：干系人参与管理。

### 2. 干系人管理链路

1. 识别干系人；
2. 记录到干系人登记册；
3. 分析权力、利益、影响、态度和期望；
4. 制定干系人参与计划；
5. 管理参与并建立信任；
6. 使用参与度评估矩阵比较当前与期望状态；
7. 持续调整策略。

### 3. 权力—利益方格

| 权力 | 利益 | 策略 |
|---|---|---|
| 高 | 高 | 重点管理 |
| 高 | 低 | 令其满意 |
| 低 | 高 | 随时告知 |
| 低 | 低 | 监督，投入最少必要精力 |

凸显模型进一步使用权力、合法性和紧急程度分类。项目经理还应分析向上、向下、横向和外部影响方向。

### 4. 敏捷角色

| 角色 | 主要职责 |
|---|---|
| 产品负责人 | 愿景、路线图、待办列表、价值排序、验收反馈 |
| 团队促进者/Scrum Master | 服务型领导、消除障碍、保护团队、促进实践 |
| 开发团队 | 跨职能、自组织、估算、承诺、决定如何交付 |
| 干系人 | 提供需求、反馈、业务判断和验收参与 |

客户很少参加评审时，优先**教育其参与的重要性、澄清期望和建立反馈机制**，而不是让团队替客户猜需求。

## 第十四记：确保知识交流

知识传递包括显性知识和隐性知识。文件只能解决部分问题，还需要培训、辅导、结对、工作坊、实践社区和共同工作。

### 培训闭环

1. 识别能力差距；
2. 确定培训/辅导方案；
3. 安排预算、时间与资源；
4. 实施；
5. 衡量效果；
6. 更新资源管理计划、知识库和经验教训。

### 常见场景

- 新成员不熟悉流程：培训+辅导；
- 团队首次使用敏捷：敏捷教练支持，而不是直接替换全部人员；
- 另一团队Scrum实践困难：评估成熟度并提供指导；
- 文档过多影响效率：保留足够支持交付、合规和维护的最小必要文档。

## 第十五记：管理项目问题

### 风险、问题、变更的分流

![问题变更收尾边界](/donot-eat-fish/img/project-management/pmp-exam/issue-change-closure-boundaries.png)

- 已发生：记录问题日志；
- 先分析根因、影响和责任人；
- 在团队权限内解决；
- 若需要改变基准、合同或已批准计划，提交变更请求；
- 处理后更新状态和经验教训。

敏捷团队发现问题时，应尽快透明化。技术障碍通常在每日站会提出，不应等到回顾会或评审会才暴露。

### 敏捷状态工具

| 工具 | 主要用途 |
|---|---|
| 看板 | 流程可视化、WIP限制、拉动式工作 |
| 燃尽图 | 剩余工作趋势 |
| 燃起图 | 已完成工作和范围变化 |
| 累计流量图 | 在制品、吞吐、瓶颈和流动稳定性 |
| 任务板 | 即时任务状态，偏物理可视化 |
| 仪表盘/信息发射源 | 多维项目状态透明展示 |
| 每日站会 | 15分钟同步进展与障碍，详细讨论会后进行 |

## 第十八记：定义团队基本规则

团队章程用于建立：

- 价值观与行为准则；
- 会议规则、准时要求和决策程序；
- 冲突解决方式；
- 沟通渠道和工作时间；
- 对质量、协作和责任的共同承诺。

### 资源管理文件辨析

| 文件/工具 | 作用 |
|---|---|
| RBS | 资源分类和层级结构 |
| RAM | 工作与组织资源的对应关系 |
| RACI | 谁负责、谁批准、谁咨询、谁知情 |
| WBS | 可交付成果分解，不直接解决职责冲突 |
| 资源管理计划 | 角色职责、团队建设、获取、释放、培训、认可等 |
| 团队章程 | 行为、会议、决策和冲突规则 |

## 第十九记：建立团队

### 1. 获取资源

内部获取通过与职能经理、其他项目经理和人力资源协商；外部获取通过采购。项目经理应明确技能、时间、地点和成本要求，不能只提出“给我最优秀的人”。

### 2. 谈判

理想策略是双赢：关注利益而非立场，使用客观标准，明确可交换条件和底线。对唯一供应商报价偏高，应先做独立估算、市场分析和谈判，而不是无依据接受或强硬拒绝。

### 3. 虚拟团队

常见问题：沟通缺失、信任不足、文化差异、时区冲突、信息分散。

解决方法：

- 尽可能举行面对面或虚拟启动会；
- 建立清晰工作协议和沟通节奏；
- 使用共享看板、日历、知识库、燃尽/燃起图；
- 定期视频交流，避免仅靠邮件；
- 工作频道和非工作频道分离，减少信息噪声；
- 尊重文化差异并设计包容性会议。

## 第二十记：领导团队

### 1. 服务型领导

敏捷环境中，领导者重点是：

- 明确愿景和边界；
- 保护团队免受无序干扰；
- 消除障碍；
- 促进团队自主决策；
- 建立信任和心理安全；
- 帮助团队成长，而不是替团队分配每个任务。

### 2. 情境领导

| 团队状态 | 适合风格 |
|---|---|
| 能力低、意愿低/不确定 | 指导型：明确任务与方法 |
| 能力提升但仍需支持 | 教练型：解释、示范、反馈 |
| 能力较高但信心/动力波动 | 支持型：参与、鼓励、共同决策 |
| 能力与意愿都高 | 授权型：明确目标与边界，放手执行 |

其他风格：交易型强调奖惩；变革型用愿景激发改变；魅力型依赖个人影响；放任型只适合高度成熟且风险较低的团队。

## 第二十一记：运用情商

情商包括自我意识、自我管理、社交意识、关系管理和内在动机。

题干出现消极、抵触、情绪低落、个人原因影响验收时，正确做法通常是：

1. 私下沟通；
2. 积极倾听和同理；
3. 了解事实、动机和约束；
4. 共同确定行动；
5. 必要时记录并跟踪绩效改进。

直接警告、隔离、替换往往过早。

## 第二十二记：向团队授权

授权不是放弃责任。项目经理仍负责愿景、治理、风险边界和结果透明，团队负责在边界内决定“如何完成”。

适合授权的情形：团队有能力和意愿、任务风险可控、需要培养能力、决策需本地信息、时间允许。敏捷环境中应建立合作决策环境，而不是要求项目经理决定每个迭代的全部任务。

## 第二十三记：支持团队绩效

### 1. 绩效反馈

新成员已经培训但仍无法按时完成任务时，优先与其直接讨论，形成**具体、可测量、有期限的改进行动计划**，再判断是否需要额外培训、岗位调整或升级。

### 2. 激励理论考试要点

- 马斯洛：生理、安全、归属、尊重、自我实现；
- 赫茨伯格：保健因素只能减少不满，激励因素促进投入；
- X理论：人需严格控制；Y理论：人在适当条件下愿意负责；
- 成就动机：成就、权力、亲和需要；
- 内在动机通常比单纯外在奖励更适合知识工作和敏捷团队。

### 3. 团队发展

塔克曼：形成→震荡→规范→成熟→解散。冲突在震荡期常见，不应立即判定团队失败；领导风格应随成熟度调整。

## 第二十四记：管理冲突

### 冲突策略

| 策略 | 结果 | 适用 |
|---|---|---|
| 合作/解决问题 | 双赢、长期解决 | 默认首选，重要问题、多方共识 |
| 妥协 | 双方部分满意 | 时间有限、临时可接受 |
| 缓解/包容 | 强调一致、弱化差异 | 关系优先、问题较小 |
| 撤退/回避 | 暂不处理 | 冷却、低优先级、信息不足 |
| 强迫 | 一方赢 | 紧急、安全、必须快速决策 |

考试原则：先私下直接沟通，理解冲突来源，合作解决；在团队无法解决、超权限或严重违规时再升级。

## 第二十五记：解决障碍、妨碍和阻碍

处理步骤：识别→评估影响→排序→确定责任→移除/减轻→跟踪→复盘。

- Scrum Master应保护团队免受频繁外部打扰；
- 新干系人不断质疑团队导致生产力下降，应建立正确的信息接口和参与机制；
- 数据缺少强制参数已成为现实问题，应立即在每日站会暴露；
- 瓶颈可通过WIP限制、流程分析、跨职能协作和自动化改善。

## 第二十六记：与干系人协作并凝聚共识

敏捷四大价值观：

1. 个体和互动高于流程和工具；
2. 工作的产品高于详尽文档；
3. 客户协作高于合同谈判；
4. 响应变化高于遵循计划。

“高于”不等于后者没有价值，而是发生冲突时优先前者。

### 共识形成方法

- 明确共同愿景和成功标准；
- 让受影响干系人尽早参与；
- 使用引导式研讨会呈现事实、约束与选项；
- 区分立场和真实利益；
- 用原型、演示和数据减少抽象争论；
- 记录决定、责任人和后续验证点。

## 人员域综合记忆

> **先建立共同愿景，再设计沟通和参与；先理解人和事实，再解决冲突和绩效；领导者负责环境、边界和障碍，团队负责专业判断和自主交付。**
