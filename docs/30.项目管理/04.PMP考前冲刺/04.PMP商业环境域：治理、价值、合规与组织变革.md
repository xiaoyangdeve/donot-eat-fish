# PMP商业环境域：治理、价值、合规、组织变革与外部环境

2026新版PMP将商业环境域提高到26%。这意味着项目经理不能只关注范围、进度和成本，还要持续回答：

> 项目是否仍值得做？是否符合战略和法规？组织是否能接受变化？外部环境是否改变了价值、风险和范围？

![商业环境与价值交付](/donot-eat-fish/img/project-management/pmp-exam/business-environment-value-delivery.png)

## 第二记：制定项目治理结构

![治理结构与升级路径](/donot-eat-fish/img/project-management/pmp-exam/governance-escalation-path.png)

### 1. 治理的组成

- 决策权和授权边界；
- 阶段门、报告和审查机制；
- 成功指标；
- 变更审批路径；
- 风险和问题升级阈值；
- 伦理、政策、合规和审计要求；
- 项目与项目集、投资组合和运营之间的接口。

### 2. 关键治理角色

| 角色 | 核心职责 | 典型题干 |
|---|---|---|
| 项目发起人 | 授权、资金、商业可行性、重大障碍 | 裁员影响25%团队、项目无法获得资金、战略优先级冲突 |
| 指导委员会 | 重大决策、阶段门、优先级和跨部门监督 | 高管要求范围监督、重大项目方向判断 |
| PMO | 方法、模板、审计、共享资源、经验教训、辅导 | 多项目资源排序、持续改进、方法标准化 |
| 项目经理 | 在治理框架内整合和执行 | 分析影响、准备信息、升级超权限问题 |
| 职能经理 | 提供和管理专业资源 | 资源被调走、资源日历和绩效接口 |

### 3. PMO类型

- 支持型：提供模板、培训、最佳实践，控制程度低；
- 控制型：要求遵循框架、模板和审计，控制中等；
- 指令型：直接管理项目，控制程度高。

PMO为持续改进提供建议时，应重点使用**标杆对照、经验教训、绩效数据和审计发现**，而不是只依赖认证数量或问卷。

### 4. 升级原则

- 先在项目经理权限内分析、协商；
- 资源冲突跨项目时，可由PMO/项目集治理排序；
- 项目可行性、资金、战略或大规模裁员影响，应与发起人讨论；
- 不应绕过治理，直接改变范围、预算或期限。

## 第二十八记：评估并交付项目利益和价值

### 1. 商业论证、章程和收益管理计划

| 文件 | 回答的问题 | 典型内容 |
|---|---|---|
| 商业论证 | 为什么要做、是否值得做 | 可行性、成本收益、战略一致性、主要选项 |
| 项目章程 | 正式授权做什么、谁负责 | 项目目标、高层级需求/范围/风险、成功标准、PM任命 |
| 收益管理计划 | 收益何时由谁实现和衡量 | 目标收益、战略一致性、责任人、时间表、指标、风险 |
| 项目管理计划 | 如何管理与交付 | 基准、子计划、治理、执行和控制规则 |

当预算和资源估算远高于原始预期时，项目经理不能先擅自缩范围或要求增加预算，而应**重新审查商业论证，确认收益和约束是否仍有效**。

### 2. 价值不等于按时按预算

新版PMP把成功从传统“范围、进度、成本”扩展到：

- 利益相关方价值；
- 期望业务结果；
- 投入是否值得；
- 运营是否真正采用；
- 收益是否持续实现。

项目可能按时、按预算、满足范围却让客户不满意，说明需求、期望、质量或价值管理失败。

### 3. 价值交付手段

- 与关键干系人共同定义价值；
- 建立可衡量指标和收益责任人；
- 优先交付高价值、高风险降低和高学习价值工作；
- 使用MVP和增量交付验证假设；
- 迭代评审中检查成果和价值，而不只汇报完成数量；
- 持续评估商业论证，必要时调整或终止项目。

### 4. 财务评价指标速记

- NPV：考虑货币时间价值，通常越高越好；
- IRR：使NPV为零的折现率，通常越高越好；
- 回收期：收回初始投资所需时间，越短越好但忽略后续价值；
- ROI：投资收益相对投资成本的比例。

## 第二十七记：支持组织变革

### 1. 组织变革不是只培训工具

敏捷转型或新系统上线失败，常见原因包括：组织孤岛、绩效指标冲突、管理层不授权、角色边界不清、文化不接受试错、运营流程未改变。

### 2. 变革实施原则

1. 评估组织文化、准备度、影响群体和阻力；
2. 获得高级领导支持与明确愿景；
3. 识别变革倡导者；
4. 使用试点获取证据和反馈；
5. 培训、辅导和沟通；
6. 调整治理、绩效、角色和流程；
7. 迭代推广并衡量采用率和业务结果。

### 3. 常见模型

- ADKAR：认知Awareness、意愿Desire、知识Knowledge、能力Ability、巩固Reinforcement；
- Kotter八步法：紧迫感、联盟、愿景、传播、授权、短期成果、巩固、制度化；
- 组织变革迭代模型：评估→设计→实施→反馈→调整；
- 萨提亚变革模型：旧状态、外来因素、混乱、转化、练习整合、新状态。

考试题中遇到大量抵制时，通常先寻求高层支持和共同愿景，而不是同时强制所有项目切换敏捷。

## 第二十九记：规划和管理项目合规性

### 1. 合规管理流程

1. 确认法规、合同、政策、安全、健康、可持续性等要求；
2. 分类合规类别；
3. 识别潜在不合规威胁；
4. 分析后果；
5. 确定控制、责任人和证据；
6. 将检查嵌入质量、风险、采购、配置和变更流程；
7. 衡量合规程度并报告；
8. 对偏差进行根因分析、纠正和持续改进。

### 2. 合规应“内建”

敏捷项目不能为了加速交付，把安全或合规检查推迟到最终发布。应将合规要求纳入待办列表、DoD、验收标准、自动化测试和每次部署检查。

### 3. 发现不合规后的行动

安全审计发现违规行为时，优先组织相关团队进行根因分析并制定纠正措施，而不是降低问题等级或只检查计划是否写过要求。之后更新风险、质量、问题、变更和经验教训工件。

### 4. 法规与质量

法律法规、行业标准和组织政策属于规划质量的重要输入/约束。项目质量计划必须明确如何满足这些要求及如何形成合规证据。

## 第三十记：评估并应对外部业务环境变化

### 1. 外部环境因素

- 法律法规与监管政策；
- 技术变化、网络安全、AI；
- 市场需求、竞争对手和价格；
- 经济、汇率、通胀和融资；
- 地缘政治、供应链；
- 环境与可持续性；
- 社会和文化变化。

### 2. EEF与OPA

| 概念 | 含义 | 示例 |
|---|---|---|
| 事业环境因素EEF | 团队通常不能直接控制，但会影响项目 | 法规、市场、组织文化、基础设施、资源可用性 |
| 组织过程资产OPA | 组织可积累、更新和复用的资产 | 模板、流程、知识库、历史数据、经验教训 |

公司新规定“所有IT项目必须使用第三方云基础设施”属于组织内部环境约束，通常作为EEF影响项目；历史风险资料、模板和知识库属于OPA。

### 3. 外部变化的处理链

1. 持续扫描；
2. 识别对范围、待办列表、价值、合规、风险、成本和进度的影响；
3. 与关键干系人评估优先级；
4. 预测型通过变更控制调整；敏捷型重排待办列表；
5. 更新商业论证和收益预期；
6. 沟通并监督结果。

### 4. 已发生的不合规属于问题

开工会上发现可交付成果已经不符合环境法，这是一个**已发生的合规问题**，应进入问题日志并立即处理；若只是未来可能不符合，才记录为风险。

## 持续改进：连接所有商业环境任务

2026新版ECO将持续改进明确列入商业环境域。项目经理应：

- 利用经验教训，不等到收尾才总结；
- 更新流程、模板和组织过程资产；
- 使用审计、回顾会、根因分析和数据趋势改进系统；
- 关注业务结果，而非只完成活动；
- 将改进措施分配责任人、期限和验证指标。

## 商业环境域综合记忆

> **治理回答谁有权决定，商业论证回答为什么值得做，收益管理回答价值如何实现，组织变革回答人和系统如何采用，合规回答什么不能违反，外部环境回答项目为什么必须持续调整。**
